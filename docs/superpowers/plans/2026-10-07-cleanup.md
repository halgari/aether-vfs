# aether-vfs cleanup pass: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development.
> Streams A, B, C and M run in parallel, each in its own worktree. Within a stream, tasks run in
> order.

**Goal:** Fix the bugs the audit found, then delete dead code, define each repeated thing once,
split oversized files, and make tests, CI and docs trustworthy. Behaviour stays the same.

**Spec:** `docs/superpowers/specs/2026-10-07-cleanup-design.md`. The audit reports in
`docs/superpowers/specs/2026-10-07-cleanup-audit/` hold the detail for every finding ID used
below: file:line evidence, the exact proposed change, and its risk. **Read the report section for
each finding in your task before changing anything.** The report's "proposed change" is the
requirement unless this plan or the spec says otherwise.

## Global constraints

- **Behaviour.** Nothing changes except the listed bug fixes (T3, E4, E3, E9, T6, the Linux
  builds of vfs-launch and vfs-redirect) and T2 (`stored_name` forwarding).
- **Formats.** No change to the wire, the ring layout, opcode numbers, the `overlay.reg` format
  version, or the storage format.
- **Commits.** Each commit either moves code or changes it, never both. Every commit message
  ends with a blank line and then
  `Claude-Session: https://claude.ai/code/session_01LpMJHm1UFrXPeWreERuLqY`.
- **Ownership.** Only touch the crates and files your stream owns (spec §3.1). The exceptions:
  workspace member lists, `Cargo.lock`, and fixing references to a crate or test you
  deleted or moved (spec §3.2).
- **Compatibility re-exports.** If you move or rename an item another stream imports, keep a
  `#[doc(hidden)]` re-export at the old path with the comment
  `// compat: removed by cleanup stream I`.
- **Haskill-facing APIs.** For vfs-embed, vfs-proton, vfs-provider and vfs-storage, only
  additive changes before stream H.
- **Formatting.** Use `rustfmt --edition 2024 <file>` on the files you touch. Never run
  `cargo fmt --all` on the Haskill repo, because it walks submodules; inside aether's
  `rust/`, `cargo fmt -p <crate>` is fine.
- **Scratch space.** Never use /tmp. Use the worktree's `rust/target/` for scratch, Wine
  prefixes and test homes.
- **Safety around a running game.**
  - Don't start Skyrim and don't touch `~/.local/share/haskill`.
  - Before a Wine or Proton test run, check that `pgrep -x haskill` is empty and that
    `ps -eo args | grep -c '[S]kyrimSE.exe'` is 0. If either shows a game running, stop and
    report.
  - Kill only processes you started, by exact pid or name. Never use a `pgrep -f` pattern.
- **Subagents.** Do the work yourself and spawn none.

## Verification commands

Run from `<worktree>/rust`.

- **Linux tests:** `cargo test -p <crate>…`
- **Linux clippy:** `cargo clippy -p <crate>… --all-targets -- -D warnings`
- **Windows check and clippy:**
  `CFLAGS_x86_64-pc-windows-msvc=-Wno-error=implicit-function-declaration cargo xwin clippy --target x86_64-pc-windows-msvc -p <crate>… --all-targets -- -D warnings`
- **Shim tests under Wine:**
  1. Build with `CFLAGS_… cargo xwin test --no-run --target x86_64-pc-windows-msvc -p vfs-shim`.
  2. Run each test exe under `~/.local/share/haskill/aether/runtimes/GE-Proton11-7/files/bin/wine`
     with `WINEPREFIX=<worktree>/rust/target/wine-prefix`.
  3. Known failures at the start: 4 binaries, plus flaky `lazy_section` tests. Record the
     baseline list in your first report. A task may not add to it.
- **Proton end-to-end:**
  1. `cd <worktree> && bin/build-windows --release`
  2. `cd rust && VFS_HOME=$PWD/target/vfs-home cargo test --release -p vfs-embed --test <name> -- --ignored --test-threads=1`.
     Point the runtime at an installed GE-Proton the same way the existing tests do (see task M2).
