# Add-ons Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split aether-vfs into a lean core and an `addons/` workspace holding storage and the Steam / Nexus / Wabbajack-CDN / GOG downloaders (each with an optional `Provider` adapter), delete the unused daemon stack, and repoint Haskill at the add-ons.

**Architecture:** `rust/` (core) never depends on `addons/`. `addons/` is its own Cargo workspace that depends on core crates by path. Haskill (parent repo, `external/aether-vfs` submodule) depends on both by path and keeps thin facades (`haskill-sources`, `haskill-formats`) so its call sites barely change.

**Tech Stack:** Rust (core edition 2021 / rust 1.89; add-ons edition 2024 / rust 1.96), tokio, reqwest 0.13 (rustls), steamroom (pinned git), zstd, flate2, md-5, redb.

**Spec:** `docs/superpowers/specs/2026-10-08-addons-design.md` (read it first; this plan argues from it).

## Global Constraints

- License `GPL-3.0-only` everywhere. GOG code ported from NexusMods.App (GPL-3.0) is attributed in `addons/crates/aether-gog/README.md`.
- `addons/Cargo.toml`: `edition = "2024"`, `rust-version = "1.96"`, `publish = false`, same `[workspace.lints]` as `rust/Cargo.toml`.
- Crate names: add-ons `aether-*`, core `vfs-*`. No crate under `rust/` may depend on anything under `addons/` (check: `grep -rn 'addons/' rust/ --include=Cargo.toml` is empty).
- Network-touching tests are `#[ignore]`. Every non-ignored test is offline.
- Nexus quota rules: links signed on demand only, never ahead; cached links reused; respect the 2,000/h quota. Do not change this behaviour while moving the code.
- Commit messages end with `Claude-Session: https://claude.ai/code/session_01LpMJHm1UFrXPeWreERuLqY`.
- Move code with `git mv` inside aether-vfs (history kept). Code copied from Haskill (a different repo) names its origin commit in the commit message: `from haskill <sha> crates/<crate>`.
- Do not reformat code you are only moving; run `cargo fmt` on the add-ons workspace once per task.

## Review Focus

1. **Case-folded paths in the depot adapters** — a game asks for `Data\Skyrim.esm` in any case; Steam/GOG manifests store one spelling. `getattr`/`open` must find it case-insensitively and `readdir` must list the manifest's spelling. (Task F1/F2 test.)
2. **Depot collisions** — the same path in two depots: the earlier depot wins, and `readdir` lists it once. (Task F1/F2 test.)
3. **Reads past EOF / spanning chunks** — a `read_at` that starts in one chunk and ends in the next, and one that starts at or past the file length (returns 0, not an error). (Tasks D, F1, F2.)
4. **GOG token expiry mid-session** — an expired access token is refreshed once and the request retried; a refresh failure surfaces as a login error naming the fix, never a panic or infinite retry. (Task D test with a fake token endpoint.)
5. **Corrupt chunk** — a GOG chunk whose compressed MD5 does not match is retried per `RetryPolicy` and then reported as `SourceError::CorruptPart`, never served. (Task D test.)

use std::sync::Arc;

use crate::Storage;

/// The [`vfs_embed::RegistrySync`] for a registry layer taken from `storage`
/// ([`Storage::layer`]): [`Storage::sync`], with its error as the provider
/// status ([`crate::StorageError::to_status`]). Holds the storage weakly, so

pub fn registry_sync_for(storage: &Arc<Storage>) -> vfs_embed::RegistrySync {
    let weak = Arc::downgrade(storage);

        Some(s) => s.sync().map_err(|e| e.to_status()),
        None => Ok(()),
    })
}
