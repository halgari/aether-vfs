# Code review: M0–M4 director daemon rework

**Date:** 2026-08-11  
**Scope:** Uncommitted local changes (daemon, compose, cache, source, Clojure removal)  
**Verdict:** Solid vertical slice; remaining issues are mostly polish / deferred design, not blockers. Tests expanded after the review pass (all green).

## Summary

The rework lands a coherent pure-Rust control plane: gRPC director, scenario config, layered composition, block cache, remote sources, and inject e2e. Architecture matches the design doc for the read-only path. A once-over found several real gaps (missing tests, fragile process liveness, composition integration) that were fixed in this pass; remaining items are nits or documented deferrals (full CoW writes, named-pipe transport).

## Remaining open issues

### Issue 1 — Severity: suggestion
- **File:** `vfs-directord/src/registry.rs` (add_source remount)
- **Description:** Every `AddSource` rebuilds the full layered stack under a registry mutex. Fine for control-plane rates; would hurt if a client streamed thousands of sources.
- **Suggestion:** Debounce rebuild, or append-only mount when layer is max so far.
- **Status:** open

### Issue 2 — Severity: suggestion
- **File:** `vfs-cache/src/backend.rs` (file_id)
- **Description:** `file_id` is a local hash of path/size/mtime, not a source-provided etag. Renames or size-stable overwrites can collide/miss.
- **Suggestion:** Plumb `file_id` from `OpenResp` (proto already has the field) once backends expose it.
- **Status:** open

### Issue 3 — Severity: suggestion
- **File:** `vfs-compose/src/overlay.rs`
- **Description:** Read-side whiteouts only; no copy-up on write (M-Write incomplete vs design).
- **Suggestion:** Keep deferred; document in API docs that writes return bad_request.
- **Status:** open (by design)

### Issue 4 — Severity: suggestion
- **File:** `vfs-directord/src/service.rs` (Launch stream)
- **Description:** `Started.pid` is always 0; detach mode cannot report a real pid.
- **Suggestion:** Extend `Session::launch` to return `(pid, exit)` when available.
- **Status:** open

### Issue 5 — Severity: nit
- **File:** `vfs-source/src/remote.rs`
- **Description:** Sync `Backend` methods `block_on` gRPC; under load, holding a client mutex + blocking worker threads can stall.
- **Suggestion:** Per-request clients or a dedicated blocking pool with timeouts.
- **Status:** open

### Issue 6 — Severity: nit
- **File:** `vfs-directord/src/lib.rs` (auto-spawn)
- **Description:** Detached daemon stderr is discarded; failed spawn is only visible via timeout errors.
- **Suggestion:** Log to a per-user file under `%LOCALAPPDATA%/vfs-director/`.
- **Status:** open

### Issue 7 — Severity: nit
- **File:** design vs code — `SetComposition` RPC
- **Description:** Design sketch includes `SetComposition`; M0–M4 use layer+mount on `AddSource` only.
- **Suggestion:** Either implement or strike from the design doc to avoid drift.
- **Status:** open

## Risk areas

1. **Env inheritance for inject** — still process-global under a mutex; correct but serializes launches.
2. **`clear_mounts` during live ring traffic** — open handles keep `Arc` backends alive; new composition is fine, but long-lived handles can see a mix of old/new identity if remounted mid-open (control plane only adds sources pre-launch in practice).
3. **Clojure removal** — irreversible in this branch; ensure no external consumers of the jar remain.
