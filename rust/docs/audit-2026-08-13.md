# Code audit — 2026-08-13

Full-tree review following the removal of process hollowing. Covers dead code,
lint health, panic surface, test coverage, configuration surface and build
hygiene.

**Tree state:** 308 tests pass; `cargo build --workspace` and
`cargo clippy --workspace --tests` are both clean of errors and dead-code
warnings.

---

## 1. What is healthy

Worth stating, because these are deliberate properties that a reviewer should
not undo by accident.

- **The shim never panics.** `vfs-shim` has **zero** `unwrap`/`expect`/`panic!`
  in production code. That matters more than anywhere else in the tree: the shim
  runs inside the game's address space, so a panic is a game crash with no
  diagnostic. The two crates it calls into (`vfs-shared::reader`,
  `vfs-redirect::parse_full_dir_info`) do use `unwrap`, but every instance is
  provably infallible from a bounds or magic check a few lines above.
- **No TODO / FIXME / HACK / XXX anywhere** in the tree.
- **`unsafe` is concentrated where it must be** — `vfs-shim` (117),
  `vfs-inject` (34), `vfs-win` (32), `vfs-ipc` (30), `vfs-payload` (22) — and
  the pure crates have essentially none. `vfs-ipc` confines all of it to one
  segment accessor; `vfs-win` to mapping and events.
- **The pure layers are genuinely pure.** `vfs-core`, `vfs-redirect` and
  `vfs-shared` carry 44 / 41 / 23 tests against ~1k LOC each and need no OS, no
  game and no filesystem to exercise.

## 2. Findings

Ordered by what I would fix first.

### 2.1 `vfs-payload` has no tests — 497 LOC, and the most delicate in the tree

The zero-import pre-init payload runs **before `LdrpInitializeProcess`**, where
only ntdll and the EXE image are mapped. It hooks four path/attribute stubs and
takes every address it needs through a config struct because it cannot import
anything. It is the one component whose failure mode is "the process dies during
bootstrap with no logging".

It is also the only substantial crate with **zero** `#[test]`.

Much of it is testable off-target: the redirect-table encode/decode, the suffix
match, and config decoding are pure. The reflective-map and RIP-redirect halves
are not, but `vfs-inject/tests/dual_layer.rs` covers the composed path.

**Recommend:** unit tests for the pure half at minimum. This is the largest
coverage gap measured against risk.

| crate | LOC | tests |
|---|---:|---:|
| vfs-payload | 497 | **0** |
| vfs-launch | 1157 | 1 |
| vfs-directord | 2232 | 14 |
| vfs-inject | 2329 | 15 |

### 2.2 `cargo build --all-targets` cannot build this tree

Nine output-filename collisions, then `LNK1104`. Cargo emits the cdylib of
`vfs-shim-dll` and `vfs-fixture-vproxy` once as a lib unit and again as a test
dependency, both to the same path under `deps/`, and the second link fails.

Pre-existing (measured at 9 collisions before any of this week's work) and *not*
fixed by `test = false` — it is a cargo/cdylib interaction, not a manifest bug.

**Consequence:** the most natural CI invocation is the one that does not work.
Anyone adding a gate will reach for `--all-targets` first and conclude the tree
is broken.

**Recommend:** use `cargo clippy --workspace --tests`, which is collision-free
and covers lib + bins + tests. Write it down in CI config rather than leaving it
to be rediscovered.

### 2.3 Configuration is 47 environment variables, 25 of them undocumented

Every switch is read straight from the environment with an inline default, and
there is no schema, no listing and no validation. Undocumented ones include
several that change behaviour materially:

- `VFS_ALLOW_DISK_FALLTHROUGH` — whether under-root misses fall through to the
  real directory. This is the isolation invariant; a stray setting silently
  un-seals the root.
- `VFS_DISK_ONLY_ROOT`, `VFS_REJECT_FUSE_SECTION`,
  `VFS_REJECT_FUSE_DATA_SECTION`, `VFS_LAZY_NO_VEH` — each disables a serving
  path.
- `VFS_KEEP_HOST_STEAM_API` — must agree with the shim's own copy of the same
  decision, and the code says so in a comment rather than in a type.

`skyrim-live` defensively `remove_var`s two of these at startup, which is
evidence the risk is already understood.

**Recommend:** one module that enumerates the switches, their defaults and their
meaning, and reads each exactly once. Even without validation, a single list
makes the surface reviewable and gives the docs something to point at.

### 2.4 11 hand-built NUL-terminated byte strings

Clippy flags `b"NtCreateFile\0"` and friends; Rust has had `c"NtCreateFile"`
since 1.77.

This is not cosmetic here. Two literal NUL **bytes** (rather than the two-char
escape) reached the tree during this week's refactor, and although they compiled
to identical bytes, they made git and grep classify `hook.rs` and `pe.rs` as
*binary* — silently disabling diff, blame and content search on the largest file
in the project. Several searches during the refactor returned "Binary file
matches" for that reason.

**Recommend:** convert to `c"..."` literals. The construct that allowed the bug
disappears.

### 2.5 A pre-existing test-isolation flake, now fixed — but the pattern may recur

`lazy_section::eager_sections_are_freed_on_close` failed roughly one run in
three: it asserts a specific VA base became `MEM_FREE`, and a freed base is
immediately available to a sibling test reserving on another thread. Fixed by
serialising the VA-touching tests.

Nothing about the product was racy; only the observation. But the same shape —
a test asserting on process-global state while peers run concurrently — exists
wherever tests touch the hook tables, the fuse-synth handle table or the stats
counters. `hookstats` already guards against this by having its tests avoid the
globals.

**Recommend:** when adding a test that asserts on a process-global, take the
same lock rather than assuming test order.

### 2.6 Hardcoded `C:\GameLayers` defaults remain in production paths

Most are in tests and fixtures, which is fine, but two are live defaults:

- `vfs-shim/src/fuse_client.rs`: managed root defaults to
  `C:\GameLayers\runtime` when `VFS_VIRTUAL_DIR` is unset.
- `vfs-launch/src/main.rs`: `DEFAULT_LAYERS = C:\GameLayers`.

The layout moved to `C:\tmp\skyrim-*` for the current harness, so these defaults
now point at a directory that does not exist on this machine. A missing
`VFS_VIRTUAL_DIR` therefore fails late and confusingly rather than immediately.

**Recommend:** make the root a required input in the shim's config rather than a
defaulted one; there is no sensible default for "which tree am I virtualising".

### 2.7 Duplicate dependency versions

`bitflags` 1.3 + 2.13, `getrandom` 0.2 + 0.3 + 0.4, `hashbrown` 0.12 + 0.17,
`indexmap` 1.9 + newer. All transitive, mostly via the gRPC/tonic stack.

Low priority — no correctness impact — but it inflates build time and binary
size for a project whose data plane is meant to be thin.

### 2.8 `vfs-server` is documented as legacy but still shipped

Its own module docs say "Production hosts use `vfs-director`", yet `vfs-launch`
still depends on it and it carries 786 LOC and 11 tests.

**Recommend:** decide. Either it is the bench/legacy path and should say so in
its `Cargo.toml` description, or it should be retired the way `ghostly` was.

### 2.9 57 remaining clippy warnings

None are correctness issues. The largest groups: 11 nul-terminated strings
(§2.4), 6 redundant closures, 6 `sort_by` → `sort_by_key`, 5 manual
`is_multiple_of`, 4 `write!` with trailing newline, 4 "items after a test
module", 3 unannotated transmutes.

The three unannotated `transmute`s are worth doing by hand rather than with
`--fix`: they are the detour trampoline casts, where writing the types out is
genuine documentation of an ABI assumption.

## 4. Deliberately not changed

- **The `--all-targets` collision.** It is a cargo behaviour, and working around
  it (renaming crates, splitting manifests) would cost more than documenting the
  invocation that works.
- **`unsafe` density in `vfs-shim`.** 117 occurrences is proportionate to what
  the crate does; the module docs already scope where it is allowed.
- **The remaining clippy warnings.** Mechanical, and applying `--fix` in bulk
  across a tree with this much `unsafe` would produce a diff nobody can review
  against the running game.
